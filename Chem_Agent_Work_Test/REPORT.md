# Work × Chem_Agent 最小集成实验报告

## 结论

本次实验已完成。结果支持：在本次测试环境中，聊天代理可以通过本地 Python
调用 Chem_Agent 现有渲染代码，将生成的 PNG 按指定位置穿插到文字解释中。
完成本次实验不需要新增自动混排功能，也不需要修改 MCP Server 或重构核心。

证据分为两类：当前 Codex 聊天的本地命令、图片核验和用户展示确认；目标
Local Work 的结果由用户在原样复测说明后回复“ABC均完成”确认，未另行采集
目标界面的截图与运行日志。结论限定于本次样例和环境。

## 目标与结果

| 测试 | 验收要求 | 结果 |
| --- | --- | --- |
| A | 本地 RDKit 生成真实结构图；已有 PNG 在聊天正文直接显示 | 通过 |
| B | 按“文字 → 苯图 → 文字 → 硝基苯图 → 文字”混排 | 通过 |
| C | 复用现有 Chem_Agent 解析、校验和渲染代码，生成机理 PNG 并混排 | 通过 |

## 实现与交付

- 分支：`experiment/work-rendering`；未执行 Git 提交。
- `render_test.py`：生成苯与硝基苯结构图；`--verify-only` 只读核验原图。
- `chem_render_cli.py`：读取只含 `tag` 字段的 JSON，以现有严格标记调用核心。
- `03_attack.json`、`04_rearomatization.json`：复用现有 prompt 中的硝化机理样例。
- `output/`：两张结构图、两张机理图、生成清单，以及机理图对应的 TikZ 和哈希报告。
- `tests/test_work_rendering_cli.py`：覆盖非法输入在编译前被拒绝及两个机理样例。
- `docs/testing.md`：补充实验与测试入口。

核心调用链为：`parse_tags` → `validate_tag` → `render_tag` → `compile_tikz_to_png`。
校验不通过即停止；沿用现有 LaTeX 源码闸门与编译流程。

## 验证证据

- 项目 Python 环境可用，RDKit 版本为 2026.03.5，依赖检查无冲突。
- 苯与硝基苯 PNG 均为 600×400；完整解码、非空检查和原图哈希核验通过。
- 亲电进攻图为 1777×655；恢复芳香性图为 1744×655。
- 两张机理图均经图片工具打开核对，中文标签、形式电荷与红色电子流箭头可见。
- 机理图 PNG 与 TikZ 的实际文件 SHA-256 均与报告一致。
- 用户确认当前聊天实际显示为“文字 → 图片 → 文字 → 图片 → 文字”。
- 适配器测试与现有示例审计：62 项通过。
- 全量回归：1038 项通过、1 项跳过，63.84 秒。

本机首次受限执行时，MiKTeX 无法访问其用户运行数据目录；获准正常本地权限
后，同一编译入口成功。该环境要求已记录，未通过修改核心或绕过安全闸门解决。

## 结论边界

- 第二步机理图沿用项目简化画法，没有画出碱夺取质子的过程。
- 本次使用已有的正确严格标记，未验证模型面对任意新问题都能正确生成标记。
- 未验证势能图、多轮修改、长回答、多图规模、跨设备图片持久性或生产部署。
- 尚未实现“整段含标记文本自动替换为图片引用”的通用入口；这属于后续开发，
  不影响本次最小实验验收。

本次实验没有未完成的必需步骤。后续可选工作是开发并验证通用的离线自动混排
入口，将单图命令行调用推广到完整回答中的多个标记。

复现命令见 `README.md`；详细过程及用户确认见 `RESULTS.md`。
